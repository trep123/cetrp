分解实验05：网络质量探测

2026-10-11Network / Huawei#软考#网络工程师#华为#BFD#NQA

本实验在两台路由器之间分别部署 BFD（双向转发检测）和 NQA（网络质量分析），查看探测结果，并把静态路由、默认路由与 BFD/NQA 联动，链路故障时路由自动从路由表删除。

方案 1：BFD 监测网络状态

1、原理说明

BFD（Bidirectional Forwarding Detection，双向转发检测）用于快速检测系统设备之间的发送和接受两个方向的通信故障，并在出现故障时通知生成应用。BFD 广泛用于链路故障检测，并能实现与接口、静态路由、动态路由等联动检测。BFD 协议使用的默认组播地址是 224.0.0.184。

[R1] ip route-static 2.2.2.0 24 12.1.1.2

2、网络拓扑

设备 接口 IP/掩码 角色
路由器 R1 GE0/0/0 12.1.1.1/24 BFD 会话一端
二层交换机 — — 连接 R1 与 R2
路由器 R2 GE0/0/0 12.1.1.2/24 BFD 会话另一端
路由器 R2 另一侧网段 2.2.2.2/24 R1 静态路由的目的网段 2.2.2.0/24 
           <-------- BFD session -------->
[R1] GE0/0/0 12.1.1.1/24 ── [二层交换机] ── GE0/0/0 12.1.1.2/24 [R2] ── 2.2.2.2/24

3、配置过程与命令

在 R1-R2 之间部署 BFD 来检测对端的状态，R1 配置如下：

（1）路由器 R1 配置：

[R1] interface GigabitEthernet0/0/0
[R1-GigabitEthernet0/0/0] ip add 12.1.1.1 24
[R1-GigabitEthernet0/0/0] quit

[R1] bfd //开启BFD
[R1-bfd] quit
#配置R1与R2之间的BFD session
[R1] bfd bfdR1R2 bind peer-ip 12.1.1.2 source-ip 12.1.1.1 //配置BFD名称bfdR1R2，对端IP地址是12.1.1.2，本地源IP是12.1.1.1（R2配置正好相反）
[R1-bfd-session-bfd12] discriminator local 11 //本地标识符
[R1-bfd-session-bfd12] discriminator remote 22 //远端标识符
[R1-bfd-session-bfd12] commit //使用commit关键字使BFD生效
[R1-bfd-session-bfd12] quit

上述 BFD 配置，可以简化为下面 2 条命令：

[R1] bfd //开启BFD
[R1] bfd bfdR1R2 bind peer-ip 12.1.1.2 source-ip 12.1.1.1 auto //配置BFD名称bfdR1R2，对端IP地址是12.1.1.2，本地源IP是12.1.1.1，参数自动协商

[R1] ip route-static 2.2.2.0 24 12.1.1.2 track bfd-session bfdR1R2 //配置静态路由且跟踪bfdR1R2，也就是当12.1.1.1与12.1.1.2通信失败时，配置的这条静态路由会从路由表中删表

提示：原文会话视图提示符写作 [R1-bfd-session-bfd12]，与命令中的会话名 bfdR1R2 不一致（实际设备上提示符会显示所创建的会话名）。这里按原图保留，不影响命令本身。

（2）路由器 R2 配置：

[R2] interface GigabitEthernet0/0/0
[R2-GigabitEthernet0/0/0] ip add 12.1.1.2 24
[R2-GigabitEthernet0/0/0] quit

[R2] bfd //开启BFD
[R2-bfd] quit
#配置R1与R2之间的BFD session
[R2] bfd bfdR1R2 bind peer-ip 12.1.1.1 source-ip 12.1.1.2 //配置BFD名称bfdR1R2，对端IP地址是12.1.1.1，本地源IP是12.1.1.2（R1配置正好相反）
[R2-bfd-session-bfd12] discriminator local 22 //本地标识符
[R2-bfd-session-bfd12] discriminator remote 11 //远端标识符
[R2-bfd-session-bfd12] commit //使用commit关键字使BFD生效
[R2-bfd-session-bfd12] quit

上述 BFD 配置，可以简化为下面 2 条命令：

[R2] bfd //开启BFD
[R2] bfd bfdR1R2 bind peer-ip 12.1.1.1 source-ip 12.1.1.2 auto //配置BFD名称bfdR1R2，对端IP地址是12.1.1.1，本地源IP是12.1.1.2，参数自动协商

5、扩展：单臂回声 BFD

使用单臂回声方式实现 BFD，只在 R1 配置 BFD 即可，R2 不用配置 BFD（模拟器不支持）。

[Huawei]bfd // 首先需要全局下开启bfd
[Huawei-bfd]q // 退出全局bfd
bfd 123 bind peer-ip 12.1.1.2 source-ip 12.1.1.1 one-arm-echo // 创建bfd单臂回声会话
 discriminator local 123 // 本地会话号（类似于本地AS号）可以一样也可以不一样
 discriminator remote 123 //对端会话号（类似于对端AS号）可以一样也可以不一样，单臂模式中可以不用配置
 min-tx-interval 100 //报文发送时间间隔
 min-rx-interval 100 //报文接收时间间隔，单臂模式中可以不用配置
 wtr 1 //主路由链路up后等待1min后再恢复，防止抖动，默认是0
 commit // 提交生效

ip route-static 0.0.0.0 0.0.0.0 12.1.1.2 track bfd-session bfdR1R2 // 在主默认路由上挂接bfd

提示：原文此处创建的单臂回声会话名为 123，而最后一条默认路由 track 的会话名是 bfdR1R2（沿用了前面的会话名）。按原图保留；如果只配置了单臂回声会话，track 的会话名应与之一致。

方案 2：NQA 监测网络状态

1、原理说明

NQA（Network Quality Analysis，网络质量分析）是系统提供的一个特性，位于链路层之上，覆盖网络层、传输层、应用层，独立于底层硬件，可实现实时监视网络性能状况，在网络发生故障时进行故障诊断和定位。（注意：原文写作「在网络发生故事进行故障诊断」。）

NQA 通过发送测试报文，对网络性能或服务质量进行分析，NQA 支持的测试包括多种协议，例如 http 的延迟、TCP 延迟、DNS 错误、ICMP 消息等，下面以 ICMP 为例简单配置一个实例：

2、网络拓扑

设备 接口 IP/掩码 角色
路由器 R1 GE0/0/0 12.1.1.1/24 NQA 测试发起端
路由器 R2 GE0/0/0 12.1.1.2/24 被测对端 
[R1] GE0/0/0 12.1.1.1/24 ──────── GE0/0/0 12.1.1.2/24 [R2]

3、配置过程与命令

R1 配置如下：

[R1] interface g0/0/0
[R1-GigabitEthernet0/0/0] ip address 12.1.1.1 24
[R1-GigabitEthernet0/0/0] quit

[R1] nqa test-instance root icmp //创建一个nqa测试实例，测试管理账户名为root，测试实例名称为icmp
[R1-nqa-root-icmp] test-type icmp //测试类型为icmp协议测试
[R1-nqa-root-icmp] frequency 10 //指定连续两次探测时间间隔为10s
[R1-nqa-root-icmp] probe-count 2 //指定一次探测进行的测试次数
[R1-nqa-root-icmp] destination-address ipv4 12.1.1.2 //测试的对端ip地址
[R1-nqa-root-icmp] start now //启动当前测试例
[R1-nqa-root-icmp] quit

注意：原文写作 strat now，正确命令为 start now。

R2 配置如下：

[R2] interface g0/0/0
[R2-GigabitEthernet0/0/0] ip address 12.1.1.2 24
